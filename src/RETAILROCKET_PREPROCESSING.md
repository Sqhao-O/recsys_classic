# RetailRocket 用于 DIN 的预处理建议

当前代码保留普通 Embedding L2，训练和验证默认取消样本上限，并支持 CUDA。以下稀疏统计来自此前的限量阶段；频次过滤和会话去重仍是后续建议，尚未加入预处理。本次只修改代码，训练数据需要在目标环境中重新生成。

## 先明确稀疏统计的口径

此前“86.27% 的商品只出现一两次”是指：限量保留的 16 万条训练样本中，作为正候选或负候选出现过的 91,614 个商品，有 86.27% 的候选出现次数不超过 2。它不等于这些商品在原始日志中只被浏览过一两次，也不包含商品作为历史输入的次数。

本地清洗后，完整训练期（含预热）中，原始浏览次数不超过 2 的商品占 47.31%。此前限量的 8 万条正样本涉及 36,954 个商品，其中正样本次数不超过 2 的商品占 78.44%。原始长尾和抽样丢失训练机会同时存在。

以现有窗口和时间边界统计，559,162 条浏览能形成有严格过去历史的训练正样本。这里沿用现有历史规则，尚未应用下面的会话去重或历史商品过滤：

| 有效正样本最小次数 | 商品数 | 对应有效正样本数 |
| --- | ---: | ---: |
| 5 | 27,061 | 436,574 |
| 10 | 13,743 | 349,472 |

如果保留这 27,061 个商品，要求每个商品至少有 5 条真正用于训练的正样本，最低就需要 135,305 条正样本。旧的 80,000 条正样本预算无法满足，因此当前默认取消了训练和验证的样本数量上限。全量数据重新生成后，应再次统计实际训练支持度；原始低频商品仍然存在。

## 公开资料支持哪些做法

没有找到适用于本项目任务、被证明普遍最优的 RetailRocket + DIN 预处理配置。会话下一商品推荐、采样二分类、真实曝光 CTR 的数据和指标不同，不能直接比较。

GRU4Rec 作者公开的 RetailRocket 脚本以 1 小时不活跃间隔切分会话，保留 view，合并同会话连续重复商品，迭代过滤单事件会话和少于 5 次交互的商品；末 7 天用于测试，再从此前数据中留出验证期。这是可复现的会话推荐参考，不是 DIN 必须采用的规则。该脚本先做全量过滤再划分；本项目采用训练期统计确定商品集合，避免用验证期频次筛选商品。[作者的 RetailRocket 脚本](https://github.com/hidasib/gru4rec_third_party_comparison/blob/master/retailrocket_preproc.py)

DIN 原论文的公开实验使用 Amazon 和 MovieLens，并未使用 RetailRocket。Amazon 实验使用用户和商品都有较充分交互的数据，输入包含商品 ID、类别及对应历史；对每个用户使用多个历史前缀构造样本。作者建集代码保留各个训练前缀并配负样本，没有当前这种统一截成 8 万条正样本的步骤。[DIN 论文第 6.1 节](https://arxiv.org/html/1706.06978#S6.SS1)、[作者建集代码](https://github.com/zhougr1993/DeepInterestNetwork/blob/master/din/build_dataset.py)

RecBole 支持用户/商品交互频次区间过滤，低频过滤是常见的数据准备手段，但具体阈值需要验证。只约束商品频次不应叫作“用户和商品均为 5-core”；若约束用户和商品两侧，需要迭代到稳定。[RecBole 数据配置](https://recbole.io/docs/user_guide/config/data_settings.html)

## 对当前 DIN 的具体建议

1. 当前样本起点固定为北京时间 `2015-07-02 00:00:00`，由 `sample_start_date` 设置，不再按类别覆盖率自动选窗。保留历史预热和全局时间边界，所有频次阈值仅根据训练期确定。
2. 根据完整训练数据能生成的有效正样本次数，先从 `min_item_positive_count=5` 开始筛选商品，负样本次数不能计入这个阈值。5 是起始实验值，不是已经验证的最优参数。
3. 学习版先限定到频繁商品：候选目标、历史商品和负采样池使用一致的商品集合，历史仍严格只使用过去。过滤后重新检查历史是否为空、最终有效正样本次数是否达标，必要时迭代到稳定，再建立紧凑商品词表。
4. 当前已默认保留完整的训练、验证正负样本对。后续加入频次过滤时继续保留全部；只有需要小规模实验时才考虑按商品保证支持度的抽样，不通过复制同一条样本凑次数。
5. 负商品来自当前时刻之前出现过的合格商品，继续排除用户过去和当前同时浏览的商品。每个正样本配一个负样本，暂不叠加新的负采样策略。记录负商品的类别缺失率，检查它是否形成标签捷径。
6. 商品表示继续为商品 ID Embedding 与类别 Embedding 的拼接，供 DIN 注意力使用。NPZ 字段和模型结构可以保持不变；词表大小更新后重新初始化、训练模型，保留当前 L2。
7. 报告最终实际参与训练的商品数、正样本次数分布、验证候选中未训练 ID 的比例、因低频或新商品被排除的数量，以及类别覆盖率。以上是频繁商品、有历史用户的评估范围；过滤导致 AUC 变化不能直接解释为整体业务效果提升。

会话切分和连续重复浏览合并可以作为后续独立修改。1 小时来自上述会话推荐脚本，不是本项目已验证的 DIN 最优历史跨度；当前先解决训练支持度与样本预算之间的矛盾。真实业务若要覆盖长尾和新商品，还需增加未知商品 ID 与类别属性回退，并单独评估，不能把它们直接当补齐 0 后遮掉。
